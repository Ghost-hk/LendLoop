# Section 4 — UI

Every screen, built on Section 3. Visual world chosen via Impeccable: **Shadow Board** (reference sketch: `.impeccable/mocks/decision/model-pick.html`).

## Job and audience

Neighbors on phone or laptop. Public visitors decide whether to sign in (Persuade). Signed-in neighbors browse, list, request and answer requests (Operate). Admins moderate (Operate).

## Selected direction: Shadow Board

The neighborhood's shared tool wall: a tool on loan leaves its painted outline behind.

- **Palette:** paper `#F4F1EA` ground · ink `#1B1B1B` rail and text · hardboard `#C9A270` only behind the tool wall · safety yellow `#F4C20D` for active and primary (always as a fill with ink text, never yellow text on paper) · tag red `#D7262E` for overdue and attention counts. Dark mode keeps the same roles on an ink ground.
- **Type:** Barlow for reading at one body size; Barlow Condensed uppercase for page titles and tool names only.
- **Signature move:** each tool tile shows its category icon large on a board panel. **Home** = solid ink stroke. **Out on loan** = dashed yellow stroke on an ink panel, the painted outline left on the wall. One Lucide icon per category, so the move is real vector strokes, not a picture.
- **Status tags:** kraft hang tags carrying a plain word, so state never relies on colour alone: *On the wall* · *Out · back Nov 18* · *Request pending* · *Overdue 2 days* · *Yours · 1 request*.
- **Pegboard texture** appears only on the Browse wall and the public wall. Every other screen stays plain paper. That restraint is what keeps it from becoming a costume.

## Scope and routes

| Route | Mode | Content |
| --- | --- | --- |
| `/` | Persuade | Logo, tagline, one-line pitch on trust and privacy, the public tool wall (name + category, home tools only), "Sign in to lend or borrow", three-step how-it-works. |
| `/app` | Operate | Tool wall: category chips, tiles with signature icon, owner name + Trusted badge, hang tag, "Request to borrow" dialog. |
| `/app/listings` | Operate | Your tools, "Hang a tool" dialog, edit, remove (blocked with reason when on loan), pending count linking to Incoming. |
| `/app/requests` | Operate | Your borrow requests as loan rows; cancel while pending; overdue tag. |
| `/app/incoming` | Operate | *Needs your answer* (approve/decline) first, then *Out on loan* (mark returned), then *History*. |
| `/app/admin` | Operate | Tabs: Loans (all), Listings (remove any), Neighbors (Trusted Lender toggle). Rail link only for admins. |
| `/sign-in`, `/sign-up` | — | Clerk components themed to the palette. |

## Shell

- **Desktop:** ink left rail (logo in yellow, nav, red count on Incoming, user menu at the bottom); content on paper.
- **Mobile:** ink top bar with logo and menu button; the rail becomes a sheet. Primary actions stay reachable at thumb height.

## States and ranges

- **Tools:** 0 to 200 on the wall, names up to 80 characters (tiles clamp to 2 lines), descriptions up to 500 (clamped, full text in the request dialog).
- **Loading:** skeleton tiles and rows in the same shapes.
- **Empty:** wall ("No tools in Garden yet"), listings ("Hang your first tool"), requests ("Find something on the wall"), incoming ("Nothing waiting on you").
- **Errors:** `ConvexError` codes mapped to toasts with plain words.
- **First sign-in race:** the shell waits for `users.queries.current` before rendering children.
- **Request dialog:** date range calendar with booked and past days disabled, 30/90-day limits, optional note with a counter, and booked ranges listed as text for screen readers.
- **Automation slot:** each loan row reserves a line for Section 8 activity.

## Constraints

- WCAG 2.2 AA: contrast checked per pair, focus rings in ink/yellow, 44px touch targets, `prefers-reduced-motion` respected.
- Standard controls only (shadcn/Base UI). The world supplies type, palette, density and the signature move, never the layout or the controls.
- No tool photos.
